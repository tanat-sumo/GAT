# Gold Algo Trading (Paper Only)

MA-cross 5min strategy, adapted from an NQ/MNQ setup, being tested on gold futures (GC/MGC). **Not validated yet — see status.**

## Status (2026-09-18)
- Baseline backtest (yfinance, 60d, GC=F): positive but cherry-picked-looking (+$1,727 on ma20/stop8/rr2).
- Grid sweep across ma/stop/rr (45 configs, same 60d): **only 10/45 profitable, median Sharpe -1.47.** Edge is fragile / param-sensitive on this sample. Overfitting risk.
- **Session filter DISCARDED (2026-09-18).** Multi-window walk-forward (`scripts/wf_session.py`, 6 independent windows, fixed configs): baseline is profitable in only **2/6** windows — its whole +$933 is two good weeks in late July/early Aug. The session filter's apparent advantage does not survive a control test: rotating the same 8h window through all 24 start hours puts 13-21 ET **9th of 24**, with 17/24 rotations positive and a -$1,354..+$2,398 spread across arbitrary start hours. Per-hour P&L correlates **-0.34** train vs test. No stable time-of-day effect exists in this data. See RESEARCH_LOG.md.
- **Two bugs found and fixed:** the filter logged as "NY session, 13-21 UTC" was actually 13-21 **ET** (yfinance returns US/Eastern); `load_data` was silently dropping the first 2 bars of every backtest.
- **Live paper bot's bar-coverage bug: fixed 2026-09-18 (user approved).** `scripts/paper_trade.py` previously only inspected the latest bar per poll, and GH Actions `*/5` cron isn't honoured (5-18 min intervals, one 62-min gap observed) — **225 runs vs 443 bars, ~51% coverage** before the fix. Half of all signals were skipped, and stops touched on skipped bars were never booked, biasing live results optimistically (same-window backtest: -$285 / 26.7% WR vs live +$47 / 36.4% at the time). Now walks every bar since `last_processed_bar` in order, dry-run tested against live state before pushing. **Trades recorded before the fix (all 11 as of Sep 17) are still unreliable and shouldn't be read as evidence of anything - only trades from the fix onward count.**
- **Volatility-normalized stops DISCARDED (2026-09-18).** Tested `stop = k * ATR(14)` (entries unchanged, so no trade-count confound) over the same 6 windows, k=0.5..3.0, with three controls: matched-width fixed stops, circularly time-shifted ATR (vol decoupled), and a neutral fixed-width sweep. **No k beats the fixed 8pt stop**; adaptivity beats matched-width fixed in only 3/8 cases (mean -$625); real ATR falls inside the range of its own shifted controls 5/8 times and loses to *all* shifted controls at k>=2. Premise check said so in advance: corr(ATR at entry, trade P&L) = **0.011**. See `scripts/wf_atr_stop.py`, RESEARCH_LOG.md.
- **Bigger finding from that run's controls: the stop width is noise too.** Fixed-width sweep over 6 windows: only 3/10 widths profitable, spread -$5,267..+$1,487. A ±1.5pt fine grid around the live 8pt stop swings +$2,645 / -$915 / +$441 / **+$1,487** / +$724 / -$915 / -$2,079 — **a 0.5pt change flips the sign and moves up to $3,560, versus a total claimed edge of $1,487.** 8pt "winning" is a selection artifact (it was picked from a {5,8,12} sweep on this same sample). And the whole result dies if round-trip cost is 0.6pt instead of the assumed 0.3pt (+$14 vs +$1,487).
- **NQ/MNQ breakeven+trail DISCARDED (2026-09-18).** Widened the failed 2026-09-16 attempt into a 480-config grid (breakeven trigger 0.5-2R x trail slack 0-3x ATR x trail-MA speed x stop width x entry MA) over 6 independent windows (`scripts/wf_nq_trail.py`). **7/480 profitable; only 10/480 reach >=4/6 windows where chance alone would give ~165.** Picking the in-sample best transfers *negatively* (train/test Spearman -0.06..-0.28; each winner lands at the 8th-32nd percentile out of sample), 13/14 of the winner's one-step neighbours lose money, 6/8 top configs flip on a half-window shift, 5/8 die at 2pt cost. Root cause is upstream: `scripts/nq_entry_edge.py` shows the MA cross entry has **no forward edge vs randomly timed entries** at any horizon from 15min to 8h, so no exit rule can rescue it. Further NQ work must start at the entry.
- **Two backtester bugs found and fixed (2026-09-18), both in the trail path.** The MA trail could park a long's stop *above* the market and book a fill at a price that never traded (one case: +$964 booked 375pt above the bar's high), and the trail level was applied to the same bar it was computed from (an intrabar peek that manufactured stop-outs). Net effect: **all pre-fix `ma_trail` numbers are void**, including the 2026-09-16 "0/30, median Sharpe -11.26" - the corrected engine makes that reference config -$5,235 instead of -$15,356, and the standing explanation "the MA trail whipsaws" was largely an artifact of the backtester. Fixed-mode (non-trail) results move only slightly (gold baseline +$1,229 -> +$1,026), so earlier non-trail conclusions stand. Stops/targets now also fill at the open when a bar gaps through them. Re-checked on the fixed engine: the gold 6-window fine grid around the 8pt stop is +$2,541 / -$837 / +$521 / **+$1,540** / +$759 / -$1,025 / -$2,194 (was +$2,645 / -$915 / +$441 / +$1,487 / +$724 / -$915 / -$2,079) — the knife edge is unchanged.
- Edge margin for scale: payoff is $157 win / -$83 loss ⇒ breakeven win rate **34.6%** vs measured **35.5%**. The entire claimed edge is ~1pp of win rate.
- **Bottom line: two independent nuisance parameters (session hours, stop width) each produce a P&L spread 3-4x larger than the strategy's entire claimed edge. 60 days of 5-min gold cannot separate edge from parameter noise — more hypothesis testing on this sample has low expected value however well controlled.** The binding constraint is data, not ideas.
- **Entry screen across 5 signal families, both instruments (2026-09-18).** `scripts/entry_screen.py` generalizes the exit-rule-free screen to any entry family (Donchian breakout, ROC momentum, opening-range breakout, rolling-mean/VWAP mean-reversion, volume-spike thrust - deliberately spanning continuation *and* reversion hypotheses), reusing the same forward-move / MFE-MAE-race / random-entry-control / 6-window machinery.
  - **Gold: NO EDGE in all 12 configs.** Not one of 72 mean-move tests reaches |t| >= 2 (chance gives ~3); every family sits inside the random-entry control band at every horizon. Gold 5-min has no exploitable timing structure in this sample whether you ask it to trend or to revert.
  - **NQ: one genuine hit, and it is a fade.** A 4-hour thrust (48-bar return > 1.5 sigma) is followed by a **-22.9pt move against the thrust at 2h** (t -3.32, winsorized -3.54, control band -11.7..+10.5, percentile 0.000), i.e. **fading it** is the tradeable direction. It passes controls nothing else here has: **6/6 windows same sign**, leave-one-window-out t -2.29..-3.33, present on both sides (not sample drift), percentile 0.00-0.01 vs a direction-shuffle control, 8/9 neighbouring ROC params agree (no knife edge), MFE/MAE race +5pp at every threshold, not a thin-bar artifact (2.5x median volume at signal bars, stronger in RTH than overnight), and it decays away by 8h.
  - Caveats stated in full in RESEARCH_LOG: overlapping forward windows inflate the t-stats (de-overlapped, t falls to -1.43 and the honest effect is ~14pt not ~23pt, though it stays outside the control band), 11 families were searched, one window carries 3x the others' magnitude, and the same 60-day yfinance sample applies. **Flagged as worth a follow-up; no exit logic was built for it, deliberately.**
  - Everything else screened out on NQ too: MA cross, Donchian 20/60, volume spike, ORB 30/60min, z-score reversion, VWAP deviation.
- Still open / highest-value next step: pull longer history (1-2yr) so walk-forward windows are years, not 10-day slices. Until then, don't trust any config or switch the live config off baseline. The NQ fade candidate above is the first thing worth spending that longer history on.

## Scripts
- `scripts/fetch_data.py` — yfinance 5min GC=F, ~60d only (quick sanity check)
- `scripts/ib_fetch_data.py` — IB historical bars, long history, needs IB Gateway/TWS running + paper account (see below)
- `scripts/backtest.py` — MA-cross backtest engine w/ stop/TP risk management
- `scripts/sweep.py` — param grid sweep (in-sample only, don't trust alone)
- `scripts/walk_forward.py` — proper train/test split validation
- `scripts/wf_session.py` — 6-window walk-forward + 24-hour rotation control (falsified the session filter)
- `scripts/wf_atr_stop.py` — ATR-sized stops vs fixed, with matched-width / shifted-ATR / width-sweep controls (falsified vol-normalized stops)
- `scripts/wf_nq_trail.py` — NQ/MNQ breakeven+trail 480-config grid over 6 windows, with selection / neighbourhood / window-shift / timing / cost controls (falsified the trail strategy)
- `scripts/nq_entry_edge.py` — exit-rule-free screen: forward returns and MFE/MAE race of an entry signal vs randomly timed entries. **Run this before any new grid** — a signal that fails it cannot be fixed by any exit rule. Now also hosts the reusable `screen_signal()` used by `entry_screen.py`
- `scripts/entry_screen.py` — the same screen applied to a pluggable set of entry families (Donchian, ROC, ORB, z-score/VWAP reversion, volume spike). `--scan` adds the parameter-neighbourhood + window-concentration control. Add a signal-generator function returning `(idx, sides, warmup)` to screen a new idea in ~1 minute

## IB Paper Trading Setup (required for live-history data + eventual live paper execution)
1. Create IB paper account: interactivebrokers.com
2. Install IB Gateway: ibkr.com/gateway
3. Launch, log in w/ paper account, Configure > Settings > enable API (ActiveX and Socket Clients), note port (default paper: 4002)
4. Leave running, then: `python scripts/ib_fetch_data.py --symbol MGC --duration "2 Y"`
